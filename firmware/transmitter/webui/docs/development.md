# OSS RTCM Transmitter - Development Guide

## Project Overview

Mobile-first Progressive Web App for configuring Open Survey System RTCM LoRa GNSS transmitters. Runs offline on ESP32 without internet connectivity.

## Tech Stack

- **React 18** - UI framework
- **TypeScript** - Type safety
- **Tailwind CSS v4** - Styling (mobile-first)
- **Radix UI** - Accessible component primitives (via shadcn/ui)
- **Vite 6** - Build tool
- **vite-plugin-pwa** - PWA support with service worker

## Key Architectural Decisions

### 1. State Management

- **Single source of truth**: `useConfig` hook manages all configuration state
- **Local state only**: No global state management (Redux/Zustand) - not needed for this app
- **Optimistic updates**: UI updates immediately, API calls in background

### 2. API Communication

All API calls go through `src/app/hooks/useConfig.ts`:

- `GET /api/config` - Load configuration on mount
- `POST /api/config` - Save configuration (triggers device restart)
- `POST /api/restart` - Restart device without saving
- `POST /api/wifi/scan` - Scan WiFi networks
- `POST /api/ntrip/mountpoints` - Fetch NTRIP mountpoints

**Important**: ESP32 backend does NOT validate input - validation is UI-only.

### 3. Mobile-First Design

- All components use responsive breakpoints: `sm:`, `md:`, etc.
- Touch targets minimum 44px for buttons/checkboxes
- Compact spacing on mobile, more generous on desktop
- Fixed bottom bar for primary actions (Save, Reload, Help, Restart)

### 4. PWA Considerations

- **Offline-first**: All dependencies bundled, no CDN
- **Service worker**: Auto-generated by vite-plugin-pwa
- **Geolocation**: Works in PWA installed mode, gracefully degrades in browser
- **Manifest**: Configured in `vite.config.ts`

## Coding Conventions

### TypeScript

- All new files must be `.tsx` (React) or `.ts` (utilities)
- Use `interface` for public APIs, `type` for unions/intersections
- Prefer explicit return types for exported functions
- Use `Config['section']` for partial config types

### React Components

- Functional components only (no class components)
- Props interfaces named `ComponentNameProps`
- Export component as named export (not default) for consistency
- Use controlled components for all form inputs

### Styling

- **Tailwind only** - no inline styles, no CSS modules
- Use `cn()` utility from `src/app/components/ui/utils.ts` for conditional classes
- Prefer Tailwind utility classes over custom CSS
- Font sizes/weights come from `theme.css` - don't override with Tailwind classes

### Form Handling

- Controlled inputs with `value` and `onChange`
- Validation happens on submit (in `handleSave` in `App.tsx`)
- Show validation errors via `toast.error()` from `sonner`
- No form libraries (react-hook-form installed but not used currently)

### Data Transformations

Some fields require conversion between UI and API format:

- **LoRa Frequency**: UI in MHz, API in Hz (multiply by 1e6)
- **LoRa Sync Word**: UI as hex string `0x12`, API as integer `18`
- **RTCM Message Types**: UI as comma-separated, API as array of integers

See examples in `LoRaConfig.tsx` and `RTCMConfig.tsx`.

## Adding New Features

### Adding a New Configuration Tab

1. **Update TypeScript types** in `src/app/types/config.ts`:

```typescript
export interface Config {
  // ... existing fields
  newSection: {
    field1: string;
    field2: number;
  };
}
```

2. **Create form component** in `src/app/components/config/`:

```typescript
// NewSectionConfig.tsx
import { Input } from '../ui/input';
import { Label } from '../ui/label';
import type { Config } from '../../types/config';

interface NewSectionConfigProps {
  config: Config['newSection'];
  onChange: (newSection: Config['newSection']) => void;
}

export function NewSectionConfig({ config, onChange }: NewSectionConfigProps) {
  return (
    <div className="space-y-4">
      <div className="space-y-2">
        <Label htmlFor="field1">Field 1 *</Label>
        <Input
          id="field1"
          value={config.field1}
          onChange={(e) => onChange({ ...config, field1: e.target.value })}
          required
        />
      </div>
    </div>
  );
}
```

3. **Add tab to App.tsx**:

```typescript
// Add to TabsList
<TabsTrigger value="newsection">New Section</TabsTrigger>

// Add TabsContent
<TabsContent value="newsection">
  <NewSectionConfig
    config={config.newSection}
    onChange={(newSection) => setConfig({ ...config, newSection })}
  />
</TabsContent>
```

4. **Add help content** in `src/app/data/help-content.ts`:

```typescript
export const HELP_CONTENT: Record<string, HelpContent> = {
  // ... existing content
  newsection: {
    title: "New Section Configuration",
    content: `Help text here...`,
  },
};
```

5. **Update validation** in `handleSave()` in `App.tsx` if needed.

### Adding a New UI Component

Use shadcn/ui CLI or copy from existing components:

```bash
# If component exists in shadcn/ui registry
npx shadcn@latest add <component-name>

# Otherwise, create manually in src/app/components/ui/
```

### Adding API Integration

Add new methods to `useConfig` hook:

```typescript
export function useConfig() {
  // ... existing state

  const newApiCall = async (params: string): Promise<SomeType> => {
    setLoading(true);
    setError(null);
    try {
      const response = await fetch(`${API_BASE}/new-endpoint`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ params }),
      });
      const data = await response.json();
      if (!response.ok) throw new Error(data.message);
      return data.result;
    } catch (err) {
      setError(err instanceof Error ? err.message : "Unknown error");
      return defaultValue;
    } finally {
      setLoading(false);
    }
  };

  return {
    // ... existing exports
    newApiCall,
  };
}
```

## Testing Notes

- **Geolocation**: Only works in HTTPS or localhost context
- **PWA**: Only works in production build, not dev server
- **API mocking**: No mock server - test against real ESP32 or stub responses in `useConfig.ts`
- **Responsiveness**: Test on iPhone SE (375px) and iPad (768px) viewports

## Common Issues

### Images/SVG not loading

- Use imports: `import logo from '../assets/logo.svg'`
- Or inline SVG components (like `OSSLogo.tsx`)
- Avoid direct `/public` paths - they don't work in build

### Tailwind classes not applying

- Check `theme.css` for token overrides
- Avoid text-_ and font-_ classes (defined in theme)
- Use `cn()` for conditional classes

### Form not submitting

- Check validation in `handleSave()`
- Ensure all required fields have values
- Check browser console for API errors

### PWA not installing

- Build with `pnpm run build:esp32`
- Serve over HTTPS or localhost
- Check manifest.json is accessible

## Dependencies Notes

- **Radix UI**: Don't upgrade without testing - breaking changes common
- **Tailwind v4**: Uses different syntax than v3 (CSS-first, not config file)
- **Vite PWA**: Check plugin docs before modifying workbox config
- **Sharp**: Used only for icon generation, not runtime dependency
